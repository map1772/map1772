### Что беру в работу

Чиню автоматизации, которые работают наполовину. Сценарий собран, кнопки нажимаются, в логах зелено, а заявки теряются, письма уходят дважды, счёт растёт непонятно за что. Такие сбои не падают, поэтому на демо их не видно: они видны на деньгах в конце месяца.

Конкретно: сценарии n8n и Make, которые рвутся на обрывах и повторах. Боты и ассистенты, которые уверенно отвечают неправду. Интеграции с CRM, платёжками и чужими API, где данные разъезжаются. Обвязка вокруг LLM: проверка ответа модели, стоимость запроса, защита от инструкции, спрятанной в данных.

Как это выглядит. Присылаете доступ и описание, что ведёт себя странно. За два рабочих дня возвращаю письменный разбор: где ломается, почему, сколько стоит починка, с числами. Не нашёл причину, разбор бесплатный.

### Что сейчас в работе

**[tender-digest](https://github.com/map1772/tender-digest)**: сервис на FastAPI, который принимает PDF тендерной документации и возвращает цену контракта, сроки, требования к исполнителю и штрафы. Основная работа здесь не в вызове модели, а вокруг него: скан без текстового слоя отклоняется до запроса, потому что на пустом тексте модель напишет правдоподобную выжимку; строки вида «игнорируй предыдущие инструкции» внутри документа гасятся, потому что файл присылает посторонний; повторный разбор того же файла берётся из кеша, потому что каждый запрос это деньги. Расход токенов и цена в рублях возвращаются с каждым ответом.

**[via-direct-api](https://github.com/map1772/via-direct-api)**: создание рекламных кампаний в Яндекс.Директе по текстовому брифу. Бриф превращается в структурированный план, человек его проверяет, после подтверждения кампания создаётся через официальный API v5. Разделение на два шага сделано специально: перед тем как что-то появится в чужом рекламном кабинете, это должен увидеть человек. Если цепочка падает на середине, созданное откатывается, чтобы в кабинете не оставалось половины кампании.

**[coach-memory-bot](https://github.com/map1772/coach-memory-bot)**: Telegram-бот с памятью. Держит профиль собеседника и факты, которые сам достаёт из обычной речи, и строит ответ под конкретного человека. Ответ модели приходит строгой схемой и валидируется, при нарушении идёт повтор. Отдельно закрыт слой памяти: инструкция, замаскированная под факт о пользователе, туда не попадает, на это есть тест по реально сработавшей атаке.

**[vibe-agent-toolkit](https://github.com/map1772/vibe-agent-toolkit)**: клиент с предохранителем к чужому Agent API, локальный двойник этого API и сверка документации с живым каталогом. Написан под конкретную боль: у каждой модели своё имя поля под входную картинку, и промах между ними списывает деньги молча.

**[health-index](https://github.com/map1772/health-index)**: модель оценки цифрового присутствия локального бизнеса от 0 до 100 с разбором по категориям и HTML-отчётом. Незамеренные пункты выпадают из расчёта целиком, чтобы неполные данные не занижали итог.

**[triumph-reels](https://github.com/map1772/triumph-reels)**: конвейер вертикальных роликов на Remotion. Сцены, тайминги и караоке-субтитры задаются данными, ролик пересобирается за минуты вместо ручного монтажа.

**[parser-2gis](https://github.com/map1772/parser-2gis)**: сбор карточек компаний из каталога 2GIS в готовую таблицу. На реальном прогоне 867 компаний по четырём городам через официальный Catalog API.

**[triumph-digital](https://github.com/map1772/triumph-digital)**: сайт собственного сервиса, статика плюс серверная функция приёма заявок в Telegram с защитой от абьюза.
